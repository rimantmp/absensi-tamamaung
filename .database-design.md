# Perancangan Database

Dokumen perancangan basis data untuk **Sistem Absensi Siswa Berbasis Barcode/QR — SD Inpres Tamamaung IV**.

- DBMS: MySQL 8.x / MariaDB
- Nama database: `absensi_tamamaung`
- Migration framework: Laravel Migrations
- **Lingkup dokumen:** hanya tabel yang dibangun khusus untuk domain absensi.
  Tabel bawaan Laravel (`users`, `password_reset_tokens`, `sessions`, `cache`, `jobs`, dll.)
  dan tabel package pihak ketiga (Spatie `roles`, `permissions`, pivot) **tidak termasuk** bagian perancangan ini.
  `users` disebutkan hanya sebagai referensi relasi karena dijadikan FK oleh tabel domain.

## 2. Deskripsi Tabel

| Tabel | Fungsi |
|-------|--------|
| `classes` | Master data kelas (rombel) beserta wali kelas dan tahun ajaran. |
| `students` | Master data siswa, terhubung ke akun login (`users`) dan kelas. |
| `attendances` | Catatan kehadiran harian per siswa (transaksi utama sistem). |
| `attendance_settings` | Pengaturan jam masuk, batas terlambat, dan hari aktif sekolah. |

---

## 3. Spesifikasi Tabel

### 3.1 `classes`

| Kolom | Tipe | Atribut | Keterangan |
|-------|------|---------|------------|
| id | BIGINT | PK, auto-increment | |
| name | VARCHAR(255) | NOT NULL | Nama kelas, contoh: "4-A" |
| homeroom_teacher_id | BIGINT | NULL, FK → users.id, ON DELETE SET NULL | Wali kelas (user ber-role Guru) |
| academic_year | VARCHAR(255) | NOT NULL | Tahun ajaran, contoh: "2025/2026" |
| status | VARCHAR(255) | NOT NULL, default `active` | `active` / `inactive` |
| created_at / updated_at | TIMESTAMP | NULL | |

**Constraint:** FK `homeroom_teacher_id` → `users(id)` `nullOnDelete`.

### 3.2 `students`

| Kolom | Tipe | Atribut | Keterangan |
|-------|------|---------|------------|
| id | BIGINT | PK, auto-increment | |
| user_id | BIGINT | NULL, UNIQUE, FK → users.id, ON DELETE SET NULL | Akun login siswa (1:1) |
| nis | VARCHAR(255) | NOT NULL, UNIQUE | Nomor Induk Siswa |
| nisn | VARCHAR(255) | NULL, UNIQUE | Nomor Induk Siswa Nasional |
| name | VARCHAR(255) | NOT NULL | Nama lengkap siswa |
| gender | VARCHAR(16) | NOT NULL | `Laki-laki` / `Perempuan` |
| class_id | BIGINT | NOT NULL, FK → classes.id, ON DELETE CASCADE | Kelas siswa |
| barcode_value | VARCHAR(255) | NOT NULL, UNIQUE | Kode unik QR/barcode, format `SDIT4-XXXXXXXXXXXX` |
| status | VARCHAR(255) | NOT NULL, default `active` | `active` / `inactive` |
| created_at / updated_at | TIMESTAMP | NULL | |

**Constraint & Index:**
- FK `user_id` → `users(id)` `nullOnDelete`, UNIQUE (satu siswa satu akun).
- FK `class_id` → `classes(id)` `cascadeOnDelete`.
- UNIQUE pada `nis`, `nisn`, `barcode_value`.

> Barcode dibuat otomatis saat siswa pertama disimpan (`SDIT4-` + random 12 karakter) dan tidak diubah pada edit.

### 3.3 `attendances`

| Kolom | Tipe | Atribut | Keterangan |
|-------|------|---------|------------|
| id | BIGINT | PK, auto-increment | |
| student_id | BIGINT | NOT NULL, FK → students.id, ON DELETE CASCADE | Siswa yang diabsen |
| class_id | BIGINT | NOT NULL, FK → classes.id, ON DELETE CASCADE | Snapshot kelas saat absen |
| date | DATE | NOT NULL | Tanggal kehadiran |
| check_in_time | TIME | NULL | Jam masuk (terisi jika status Hadir/Terlambat) |
| status | VARCHAR(255) | NOT NULL | `Hadir` / `Terlambat` / `Izin` / `Sakit` / `Alpa` |
| input_type | VARCHAR(255) | NOT NULL | `scan` (QR/barcode) / `manual` |
| note | TEXT | NULL | Catatan (mis. alasan izin/sakit) |
| created_by | BIGINT | NULL, FK → users.id, ON DELETE SET NULL | Petugas yang mencatat |
| created_at / updated_at | TIMESTAMP | NULL | |

**Constraint & Index:**
- UNIQUE `(student_id, date)` — satu catatan per siswa per hari (dipakai `updateOrCreate` pada absensi manual).
- FK `student_id` → `students(id)` `cascadeOnDelete`.
- FK `class_id` → `classes(id)` `cascadeOnDelete`.
- FK `created_by` → `users(id)` `nullOnDelete`.

**Alur penentuan status scan:** `check_in_time <= late_time_limit` → `Hadir`, sebaliknya → `Terlambat`. Scan berulang di hari yang sama tidak membuat baris baru (menampilkan catatan yang sudah ada).

### 3.4 `attendance_settings`

| Kolom | Tipe | Atribut | Keterangan |
|-------|------|---------|------------|
| id | BIGINT | PK, auto-increment | |
| school_start_time | TIME | NOT NULL, default `07:00:00` | Jam masuk sekolah |
| late_time_limit | TIME | NOT NULL, default `07:15:00` | Batas toleransi terlambat |
| active_days | JSON | NULL | Hari aktif sekolah, contoh: `["monday","tuesday","friday"]` |
| created_at / updated_at | TIMESTAMP | NULL | |

> `AttendanceSetting::firstOrCreate([])` — tabel dijamin hanya berisi satu baris (singleton) untuk seluruh sekolah.

## 4. Relasi Antar Tabel

| Relasi | Tipe | Keterangan |
|--------|------|------------|
| users ⇄ students | 1 : 1 | Siswa dapat memiliki akun login; `user_id` UNIQUE |
| users ⇄ classes | 1 : N | Satu user Guru menjadi wali kelas banyak kelas |
| classes ⇄ students | 1 : N | Satu kelas berisi banyak siswa |
| classes ⇄ attendances | 1 : N | Satu kelas menampung banyak catatan absensi |
| students ⇄ attendances | 1 : N | Satu siswa memiliki banyak catatan absensi |
| users ⇄ attendances | 1 : N | `created_by` mencatat banyak absensi |
| attendance_settings → attendances | 1 : N (logis) | Pengaturan menentukan status Hadir/Terlambat |

|-------|--------------------|
| students.status | `active`, `inactive` |

| students.gender | `Laki-laki`, `Perempuan` |
| users.status (ref) | `active`, `inactive` |

---

## 6. Alur Data Utama

1. **Scan mandiri / internal:** siswa (aktif) dicari via `barcode_value` → sistem hitung status terhadap `attendance_settings.late_time_limit` → insert `attendances` (input_type `scan`) atau kembalikan catatan yang sudah ada.
2. **Absensi manual:** pilih tanggal + siswa + status → `updateOrCreate` berdasarkan `(student_id, date)` → `input_type` `manual`.
3. **Laporan / riwayat:** agregasi `attendances` dengan filter tanggal, bulan, kelas, siswa, status — tanpa tabel agregasi terpisah (dihitung saat dibutuhkan).

---

## 7. Catatan Penerapan

- Enumerasi status siswa/kelas & absensi ditangani sebagai string (validasi di controller via `Rule::in(...)`, bukan enum native DB).
- Kode barcode dijamin unik dan menjadi kunci pencarian utama pada alur scan.
- Gunakan transaksi saat melakukan insert absensi bila menambahkan fitur yang melibatkan lebih dari satu write.
- Migrasi yang mendefinisikan tabel di atas: `2026_06_05_000002_create_attendance_domain_tables.php`.
